🧠 LSTM & Bidirectional LSTM Models

Standard LSTM Architecture
Input (batch_size, lookback=50, sensors=14) ↓ LSTM Layer 1: 64 units, return_sequences=True ↓ Dropout: 0.2 ↓ LSTM Layer 2: 32 units ↓ Dropout: 0.2 ↓ Dense: 16 units, ReLU activation ↓ Output: 1 unit (RUL prediction) Total Parameters: ~65,000 Training Time: 45 seconds per 100 epochs Inference: 80ms per batch
✓ Captures sequential degradation patterns
✓ Memory cells learn temporal dependencies
✓ Handles variable-length sequences
✓ Good for time-series prediction
✗ Requires GPU for reasonable training time
✗ 12x slower than XGBoost
✗ Risk of overfitting on limited dataset
✗ Only 3.8% improvement over XGBoost
Bidirectional LSTM Architecture
Input (batch_size, lookback=50, sensors=14) ↓ Bidirectional LSTM: 64 units (32 forward + 32 backward) ↓ Dropout: 0.2 ↓ Bidirectional LSTM: 32 units ↓ Dropout: 0.2 ↓ Dense: 16 units, ReLU activation ↓ Output: 1 unit (RUL prediction) Total Parameters: ~82,000 Training Time: 90 seconds per 100 epochs Inference: 120ms per batch
✓ Forward + Backward passes = richer context
✓ Better degradation understanding
✓ 7% improvement over XGBoost
✓ Captures failure mode pathways
✗ 25x slower training than XGBoost
✗ 2.4x slower inference than XGBoost
✗ GPU strongly recommended
✗ Complex to monitor and debug
⚠️ Recommendation: LSTM models show incremental improvements but slower training. Bidirectional LSTM (7% improvement) worth considering for safety-critical apps, but Transformer offers better speed/accuracy trade-off.

⚡ Transformer Model (Attention-Based)

Transformer Architecture
Input (batch_size, lookback=50, sensors=14) ↓ Multi-Head Attention: 8 heads, embed_dim=128 Query: "What features matter now?" Key: "Where is important information?" Value: "What is the information?" ↓ Feed-Forward Network: 512 units ↓ Dropout: 0.2 (prevent overfitting) ↓ Second Attention Layer (same structure) ↓ Feed-Forward Network ↓ Global Average Pooling: Over time dimension ↓ Dense: 32 units, ReLU activation ↓ Output: 1 unit (RUL prediction) Total Parameters: ~150,000 Training Time: 35 seconds per 100 epochs Inference: 100ms per batch
✓ 10.8% improvement over XGBoost
✓ Faster than LSTM (parallel attention)
✓ Attention weights show important time-steps
✓ Interpretable: See which sensors matter
✓ Captures long-range dependencies
✓ State-of-the-art architecture
✗ GPU preferred but not required
✗ 10x slower inference than XGBoost
✗ 250ms latency (batch predictions only)
✗ Larger model (35 MB)

Hybrid Ensemble Architecture
PATH 1: XGBoost Input: (samples, 35 features) [flat rolling windows] Model: XGBoost Regressor Output: Prediction 1 (RMSE 18.50) PATH 2: Transformer Input: (samples, 50 timesteps, 14 sensors) [sequences] Model: Multi-head Attention + Feed-forward Output: Prediction 2 (RMSE 16.80) COMBINATION: Final RUL = 0.40 × XGBoost_Pred + 0.60 × Transformer_Pred Weights optimized on validation set (typically: 30-50% XGB, 50-70% Transformer) Result: RMSE 16.50 (12.8% improvement)
Why Hybrid Works

XGBoost Strengths: Feature interactions, feature importance, interpretability via SHAP values

Transformer Strengths: Temporal patterns, degradation trajectories, attention-based importance

Combined: Complementary error correction - when one model fails on specific RUL phase, other succeeds

✓ 12.8% accuracy improvement (16.50 RMSE)
✓ Best overall performance
✓ Dual fallback strategy
✓ Leverages complementary strengths
✓ Non-correlated error patterns
✓ $50K+ annual additional savings
✗ 250ms inference (vs 50ms XGBoost)
✗ Requires GPU for Transformer
✗ 40x slower training (140s total)

Fallback Strategy

Graceful Degradation Path:

If Transformer latency > 200ms → Fallback to XGBoost
If Transformer RMSE > 20 → Revert to XGBoost + retrain
If GPU failure → Serve XGBoost (no inference impact)
If both models fail → Return cached ensemble predictions
